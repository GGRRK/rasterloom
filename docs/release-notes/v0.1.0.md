# Rasterloom 0.1.0 "Foundation"

Rasterloom is a native Linux raster image editor: layers, masks, selections and a
pressure-sensitive brush, reading and writing layered PSD files. This is the first milestone.
It is an original program and is not affiliated with Adobe Inc.

> Tier-0 coverage 96/105. Strict parity 15% of 709 catalogued capabilities. Weighted
> everyday-workflow coverage 44%. Ceiling is 97% - the remainder is server-side AI,
> patent-encumbered, proprietary-model or discontinued features that will never be implemented.

About 28 of the 105 tier-0 rows are individual blend modes, all covered, so the weighted
everyday-workflow figure (44%) is the better guide to what a normal editing session can do.

## What is in 0.1.0

- **Layers**: raster layers and groups (pass-through by default, or isolated), reorder, rename, duplicate,
  opacity and a separate fill opacity, visibility, lock transparency, all 27 blend modes plus Pass
  Through, layer masks (add, paint, disable, delete, apply), clipping masks with "blend clipped
  layers as group", Merge Down, Merge Visible, Flatten.
- **Selections**: rectangular and elliptical marquee, lasso, polygonal lasso and magic wand;
  new / add / subtract / intersect; Select All, Deselect, Reselect, Inverse, Feather, Expand,
  Contract.
- **Painting**: round brush (size, hardness, spacing, opacity, flow in Wash or Build-up mode,
  angle, roundness, pressure curves, airbrush, smoothing), eraser, clone stamp (aligned and
  non-aligned), paint bucket, linear and radial gradients. A whole stroke is one undo step.
- **Adjustment layers**: Levels, Curves, Brightness/Contrast, Hue/Saturation, Black & White,
  Invert, Posterize, Threshold.
- **Filters**: Gaussian Blur, Motion Blur, Unsharp Mask, Add Noise, High Pass, Offset; all
  respect the selection and show a preview.
- **Transform and image**: free transform (move, scale, rotate, skew, distort, perspective),
  Image Size, Canvas Size, Crop, Rotate Canvas 90 / 180 / arbitrary, Flip Canvas and Flip Layer.
- **Files**: native `.orp` and OpenRaster `.ora`; PSD and PSB import and export, with a merged
  composite so other programs (GIMP) show the image instead of black; PNG, JPEG and TIFF open and
  export. Saving is atomic: a failed save never damages the existing file.
- **Application**: dockable panels (Layers, History, Navigator, Tool Options, Color), saved
  workspace layouts, a 50-state History panel, an OpenGL canvas with a software fallback, and
  Help > Input Diagnostics.
- **Proof**: 418 golden renders byte-identical to an independently written NumPy reference,
  a 43-defect mutation gate (every planted defect turns at least one golden red), 12 PSD
  round-trip files checked with psd-tools, 300 unit, integration and scripted GUI tests, and a
  built-in `--selftest` that re-checks all 418 renders in under a second.

## Known limits

- No Cut / Copy / Paste, no layer mask from a selection.
- No text, pen or vector shapes, layer styles, healing tools, Dodge / Burn / Smudge, and only the
  six filters above.
- 8-bit RGB only, sRGB assumed (no ICC colour management). 16-bit and CMYK PSD files are
  converted to 8-bit RGB when opened. Canvas at most 16384 x 16384 pixels.
- Native Wayland is experimental (`RASTERLOOM_PLATFORM=wayland`); the default is X11/XWayland,
  which gives proper window decorations and a correct eyedropper everywhere.
- In the AppImage, `--license` and `--third-party-notices` on the command line print the summary
  only; the full texts are in Help > About > Licenses and inside the AppImage under
  `usr/share/doc/rasterloom/`.

## Not verified yet (read this before judging a bug)

- **Real tablets.** Pressure is tested with synthetic Qt tablet events only. Tilt, the eraser end
  and real pen drivers are unverified. This is what we most need your help with.
- **Real GPUs.** Automated tests use software rendering only.
- **The release build itself** is built by CI in an Ubuntu 22.04 container with GCC 11 and
  Qt 6.9.3, and that exact AppImage passed its self-test, a pixel-exact render and a GUI start on
  Ubuntu 22.04 / 24.04 / 26.04, Debian 12, Fedora 42, Arch Linux and openSUSE Tumbleweed
  containers. Those containers have no GPU and no tablet, so the two points above still stand.

## For testers

1. Download `Rasterloom-x86_64.AppImage` and `Rasterloom-x86_64.AppImage.sha256` into one folder
   and check the download:

   ```sh
   sha256sum -c Rasterloom-x86_64.AppImage.sha256
   ```

2. Make it executable and start it from a terminal (double-click does not work in every file
   manager, and the terminal shows any error message):

   ```sh
   chmod +x Rasterloom-x86_64.AppImage
   ./Rasterloom-x86_64.AppImage
   ```

   It needs glibc 2.35 or newer (Ubuntu 22.04+, Debian 12+, Fedora 36+, RHEL 9+, current Arch
   and openSUSE). On an older system it prints that requirement and exits. FUSE is not needed.

3. Please send back:
   - a screenshot of **Help > Input Diagnostics** while you draw a few strokes with the pen
     (and, if your pen has one, with its eraser end);
   - the output of `./Rasterloom-x86_64.AppImage --version --verbose`;
   - your distribution and version, `ldd --version | head -1`, whether you run X11 or Wayland,
     your GPU and driver, and your tablet model; if you are on X11 with a Wacom tablet, whether
     `xf86-input-wacom` is installed (without it the eraser end cannot be told apart);
   - for anything that looks wrong: what you did, what you expected, a screenshot, and the
     terminal output.

   Optional: `./Rasterloom-x86_64.AppImage --selftest` should end with `0 failed`.

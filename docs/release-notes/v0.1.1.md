# Rasterloom 0.1.1

A fix-and-import release on top of 0.1.0 "Foundation". **If you have 0.1.0, replace it:** on a
real graphics card its canvas stayed empty after opening an image.

> Tier-0 coverage 99/105. Strict parity 15% of 709 catalogued capabilities. Weighted
> everyday-workflow coverage 46%. Ceiling is 97% - the remainder is server-side AI,
> patent-encumbered, proprietary-model or discontinued features that will never be implemented.

## Fixed

- **Blank canvas on real GPUs.** With the OpenGL canvas (the default whenever a hardware GPU is
  present) an opened image was loaded - it showed in the Layers panel - but the canvas stayed
  empty. The docking framework put the canvas inside a scroll area, which switches on background
  auto-fill, and on an OpenGL widget that cleared every frame just after it was drawn. The canvas
  is now docked without the scroll area, and a new test renders the real editor window through
  the OpenGL canvas and checks every canvas pixel (it fails on 0.1.0 and passes now).

## New: getting images in and out

- **Drag and drop like you would expect**: drop image files onto an open document and each one
  becomes a new layer named after the file, centred on the canvas. With no document open, the
  first file opens and the rest are placed into it. Image data dragged from a web browser is
  placed too, and a drop that cannot be used says why in the status bar instead of doing nothing.
- **Clipboard**: Edit > Cut (Ctrl+X), Copy (Ctrl+C), Copy Merged (Shift+Ctrl+C), Paste (Ctrl+V),
  Paste in Place (Shift+Ctrl+V) and Clear (Delete), through the system clipboard: screenshots and
  images copied in other applications paste in as new layers, and copies from Rasterloom paste
  into other applications. Paste with no document open creates a document of the image's size.
- **File > Place...** adds an image file as a new layer; **Layer via Copy** (Ctrl+J with a
  selection) and **Layer via Cut** (Shift+Ctrl+J).
- **More formats**: Open, drop and Place also read GIF (first frame), WebP, BMP, TGA, ICO and the
  other formats Qt's image plugins read. File > Export adds WebP (lossless) and BMP.
- Every one of these is a render-script operation like the rest of the editor, so an exported
  session script replays pixel for pixel, and the new operations are covered by 57 new golden
  renders and three new planted-defect checks (475 goldens, a 46-defect mutation gate).

## Known limits

- Placed, dropped and pasted images become ordinary raster layers at 100 %; there are no Smart
  Objects and no "resize image during place". Pixels outside the canvas are discarded.
- No Paste Into / Paste Outside; dropping a bare web link (no image data attached) is not
  downloaded. GIF is read-only (first frame).
- The command-line tool reads only the core formats (.orp, .ora, PNG, JPEG, TIFF, PSD/PSB).
- Everything else listed under "Known limits" in the 0.1.0 notes still applies (no text, pen or
  vector shapes, layer styles, healing tools; 8-bit RGB only, no ICC colour management).

## Verified

- The OpenGL canvas was checked on a real NVIDIA GPU through a headless compositor, and CI now
  runs the real-window OpenGL canvas test on Mesa.
- The release AppImage is built by CI in an Ubuntu 22.04 container with GCC 11 and Qt 6.9.3, and
  that exact AppImage passed its self-test, a pixel-exact render and a GUI start on Ubuntu 22.04 /
  24.04 / 26.04, Debian 12, Fedora 42, Arch Linux and openSUSE Tumbleweed containers.
- Real tablets remain unverified: pressure is tested with synthetic Qt tablet events only.

## For testers

1. Download `Rasterloom-x86_64.AppImage` and `Rasterloom-x86_64.AppImage.sha256` into one folder
   and check the download:

   ```sh
   sha256sum -c Rasterloom-x86_64.AppImage.sha256
   ```

2. Make it executable and start it from a terminal (double-click does not work in every file
   manager, and the terminal shows any error message):

   ```sh
   chmod +x Rasterloom-x86_64.AppImage
   ./Rasterloom-x86_64.AppImage
   ```

   It needs glibc 2.35 or newer (Ubuntu 22.04+, Debian 12+, Fedora 36+, RHEL 9+, current Arch
   and openSUSE). On an older system it prints that requirement and exits. FUSE is not needed.

3. Please send back:
   - a screenshot of **Help > Input Diagnostics** while you draw a few strokes with the pen
     (and, if your pen has one, with its eraser end);
   - the output of `./Rasterloom-x86_64.AppImage --version --verbose`;
   - your distribution and version, `ldd --version | head -1`, whether you run X11 or Wayland,
     your GPU and driver, and your tablet model; if you are on X11 with a Wacom tablet, whether
     `xf86-input-wacom` is installed (without it the eraser end cannot be told apart);
   - for anything that looks wrong: what you did, what you expected, a screenshot, and the
     terminal output.

   Optional: `./Rasterloom-x86_64.AppImage --selftest` should end with `0 failed`.

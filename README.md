# Rasterloom

A native Linux raster image editor: layers, masks, selections and a pressure-sensitive brush,
reading and writing layered PSD files. A C++20 core with no Qt dependency, a headless
command-line renderer, and a Qt 6 Widgets desktop application. Not affiliated with, endorsed by,
or derived from Adobe Inc.

## Status: v0.1 "Foundation" - usable, early, and measured

v0.1 is the first milestone. What it does, every item proven by automated tests:

- **Layers**: raster layers and groups (pass-through and isolated), reorder, opacity, fill
  opacity, visibility, lock transparency, all 27 blend modes plus Pass Through, layer masks
  (add, paint, disable, delete, apply), clipping masks, Merge Down, Merge Visible, Flatten.
- **Selections**: rectangular and elliptical marquee, lasso, polygonal lasso, magic wand
  (tolerance, contiguous, anti-alias); new/add/subtract/intersect; Select All, Deselect,
  Reselect, Inverse, Feather, Expand, Contract.
- **Painting**: round brush with size, hardness, spacing, opacity, flow (Wash and Build-up),
  angle, roundness, pressure curves, airbrush and smoothing; eraser; clone stamp (aligned and
  non-aligned); paint bucket; linear and radial gradients; one undo step per stroke.
- **Adjustment layers**: Levels, Curves, Brightness/Contrast, Hue/Saturation, Black & White,
  Invert, Posterize, Threshold. **Filters**: Gaussian Blur, Motion Blur, Unsharp Mask, Add Noise,
  High Pass, Offset (all respect the selection).
- **Transform and image**: free transform (move, scale, rotate, skew, distort, perspective) with
  bicubic resampling, Image Size, Canvas Size, Crop, Rotate Canvas 90/180/arbitrary, Flip.
- **Files**: native `.orp` (a superset of OpenRaster, which GIMP and Krita read) and `.ora`; PSD and
  PSB import and export with a merged composite; PNG, JPEG and TIFF open and export.
- **Application**: dockable panels (Layers, History, Navigator, Tool Options, Colour), saved
  workspace layouts, History panel (50 states), GPU canvas with a software fallback, and
  Help > Input Diagnostics for tablet and GPU reports.

Every number below is generated from [`data/parity.yaml`](data/parity.yaml) by
`tools/gen_parity.py`, which refuses to count a capability unless a named test passed:

About 28 of the 105 tier-0 rows are individual blend modes, which v0.1 covers completely, so the
tier-0 figure runs ahead of the everyday-workflow figure; the weighted number is the better
guide to how much of a normal editing session is possible.

"Strict parity" means the behaviour matches the Photoshop semantics written down in
[`docs/math/`](docs/math/) and is proven byte-for-byte against an independently written NumPy
reference, never against Adobe output. The ceiling is below 100% because some features will
never be implemented: server-side generative AI, patent-encumbered algorithms, proprietary
models and discontinued features (each is a `wontfix` row with its reason).

### What v0.1 does not do yet

- No Cut, Copy or Paste, no Duplicate Layer, no layer mask from a selection.
- No text, no pen or vector shapes, no layer styles, no healing tools, no Dodge/Burn/Smudge.
- 8-bit RGB only, and sRGB is assumed: no ICC colour management, no 16-bit or CMYK editing
  (16-bit and CMYK PSD files are converted to 8-bit RGB on import).
- Canvas size is limited to 16384 x 16384 pixels; compositing is single-threaded.
- The Hand and Zoom tools, Open Recent, Repeat Filter and the Default/Swap colour shortcuts exist
  in the application but have no automated test yet, so the parity table does not count them.

### What has not been verified

- **Tablets**: pressure is tested with synthetic Qt tablet events only. Real pens, tilt and the
  eraser end need a person with a tablet (Help > Input Diagnostics shows what arrives).
- **GPU drivers**: tests run on software rendering; the GL canvas falls back to a raster canvas
  when the driver is unusable.
- **The release AppImage** is built by CI (ubuntu:22.04, GCC 11, Qt 6.9.3) and tested there on
  seven distributions. That pipeline has not run yet: it starts when the public repository
  exists. Locally the code has been built and tested with GCC 16 against Qt 6.11.2 and Qt 6.9.3,
  not yet with GCC 11.

## Running the AppImage

```sh
chmod +x Rasterloom-x86_64.AppImage
./Rasterloom-x86_64.AppImage                       # the editor (X11/XWayland by default)
RASTERLOOM_PLATFORM=wayland ./Rasterloom-x86_64.AppImage   # native Wayland (experimental)
./Rasterloom-x86_64.AppImage --version --verbose   # versions of glibc, Qt and bundled libraries
./Rasterloom-x86_64.AppImage --selftest            # built-in self-test, no window
./Rasterloom-x86_64.AppImage --cli --render-script scene.json --out scene.png   # headless renderer
```

Requires glibc >= 2.35 (Ubuntu 22.04+, Debian 12+, Fedora 36+, RHEL 9+, current Arch and
openSUSE); the AppImage says so in words on older systems. It needs no FUSE: without it, it
extracts itself to a temporary directory. Double-clicking may not work in every file manager, so
start it from a terminal the first time.

## How correctness is proven

- **Two independent implementations.** The C++ core and `tests/reference/refcomp.py` (Python +
  NumPy, binary64) are written from the same normative math documents by different authors who
  never read each other's code. Every golden render script must produce byte-identical RGBA from
  both. See [`tests/scripts/README.md`](tests/scripts/README.md).
- **Determinism.** Every script is rendered twice and the PNGs must be identical.
- **Mutation gate.** `--mutate=N` injects one of 40 known defects into the core; each must turn
  at least one golden red, which proves the tests are not vacuous.
- **Honest parity table.** [`docs/PARITY.md`](docs/PARITY.md) lists 700+ Photoshop capabilities,
  catalogued from Adobe's public user guide, with the evidence behind every claim.

## Building

Requirements: CMake 3.21+, Ninja, a C++20 compiler (GCC 11 or newer), libpng, libjpeg-turbo,
libtiff, zlib, nlohmann-json, GoogleTest (tests), and Qt 6.9 or newer (Core, Gui, Widgets,
OpenGL, OpenGLWidgets, Svg; plus the Wayland plugin for native Wayland) for the GUI. The
Qt-Advanced-Docking-System v5.1.1 is downloaded at configure time and checked against its
SHA-256 (offline: `-DFETCHCONTENT_SOURCE_DIR_QTADS=/path/to/its/source`). The test harness
and generators need Python 3 with NumPy, Pillow and PyYAML; the PSD round-trip test also uses
psd-tools when it is installed.

```sh
# Arch Linux
sudo pacman -S --needed cmake ninja gcc libpng libjpeg-turbo libtiff zlib nlohmann-json gtest \
    qt6-base qt6-svg qt6-wayland python-numpy python-pillow python-yaml
# Ubuntu 22.04 / 24.04 (Qt 6.9 is not packaged there: install it with aqtinstall and pass
# -DCMAKE_PREFIX_PATH=/path/to/Qt/6.9.3/gcc_64)
sudo apt install cmake ninja-build g++ libpng-dev libjpeg-turbo8-dev libtiff-dev zlib1g-dev \
    nlohmann-json3-dev libgtest-dev python3-numpy python3-pil python3-yaml

cmake -G Ninja -B build -DCMAKE_BUILD_TYPE=Release   # -DRL_BUILD_GUI=OFF for core + CLI only
cmake --build build
cmake --install build --prefix ~/.local --component rasterloom   # optional
```

Compile flags are fixed by the project (`-march=x86-64-v2 -O2 -fno-fast-math
-ffp-contract=off`); never add `-march=native` or `-ffast-math`, the byte-exact tests depend on it.

The AppImage is built by `packaging/build-appimage.sh` (see
[`packaging/README.md`](packaging/README.md)). A build on your own machine is a personal test
build tied to your system's glibc; the one to hand to other people comes from CI.

## Running from the build tree

```sh
build/src/rasterloom                                        # the desktop application
build/src/rasterloom-cli --render-script tests/scripts/smoke/buildspec_example.json --out out.png
build/src/rasterloom --version --verbose
build/src/rasterloom --selftest                             # the self-test the AppImage ships
QT_QPA_PLATFORM=offscreen build/src/rasterloom --smoke      # builds the main window, no window shown
```

## Testing

```sh
ctest --test-dir build -LE slow           # unit, goldens (all domains), determinism, PSD corpus, GUI
ctest --test-dir build -L slow            # the mutation gate (ids 0-42)
python3 tests/tools/run_goldens.py --cli build/src/rasterloom-cli --filter 'compositing/*'
python3 tests/tools/mutation_gate.py --cli build/src/rasterloom-cli --ids 0-42
python3 tools/gen_parity.py --ctest-junit build/ctest-junit.xml --readme README.md
```

`goldens_<domain>` tests show which areas are green. A failing golden keeps `ref.png`,
`cpp.png` and `diff.png` under `tests/output/<name>/`. The mutation gate tolerates
not-yet-implemented mutation hooks only when `RL_MUTATION_ALLOW_PENDING=1` is set.

## Naming

"Rasterloom" is an original name. The project is deliberately not named after the product it is
compatible with: describing file-format compatibility is nominative use, naming a project after
another company's trademark is not. Adobe and Photoshop are trademarks of Adobe Inc.
